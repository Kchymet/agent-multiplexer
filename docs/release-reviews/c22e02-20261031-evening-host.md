## F1 — watcher delivery retains stale coordinator routing

**Observed source:** `prWatchMembers` snapshots active members and their current root before GitHub I/O (`internal/daemon/prwatch.go:97–143`). `Poll` uses that snapshot through observation (`internal/prwatch/prwatch.go:243–316`). `enqueue` records a rendered line under the original workgroup; pending entries hold a deduplication key, text and time, not an explicit authority check. `Flush` checks age and calls `Deliver` for that workgroup, retaining deferred lines for up to two hours (`:665–686,703–744`, constants `:48–58`). [Queue and delivery source](https://github.com/Kchymet/agent-multiplexer/blob/105030b31094f8a6ff557263d5c26d4eb7a3a8ac/internal/prwatch/prwatch.go#L665).

`deliverPRWake` validates the destination exists, is unarchived and is a coordinator, and checks readiness. It then invokes host-internal `d.handle` with a prompt. It does not receive the member identities as structured input or recheck their current RootID/repository scope (`internal/daemon/prwatch.go:210–233`). The ordinary access policy explicitly says membership uses the **current** RootID and a moved member leaves scope immediately (`internal/access/policy.go:134–149`). [Delivery](https://github.com/Kchymet/agent-multiplexer/blob/105030b31094f8a6ff557263d5c26d4eb7a3a8ac/internal/daemon/prwatch.go#L210), [existing scope contract](https://github.com/Kchymet/agent-multiplexer/blob/105030b31094f8a6ff557263d5c26d4eb7a3a8ac/internal/access/policy.go#L134).

**Inference / exact affected case:** a PR transition queues while coordinator A is busy; the member is moved to B; A becomes ready before queue expiry. The source still offers the original line to A. Likewise a move during GitHub observation can leave the poll's old routing snapshot. Payload is member label/ID and PR transition/repository/URL/check metadata, not a credential or arbitrary transcript. Data already delivered before a move cannot be recalled; the concern is a new host-originated disclosure/prompt after the scope change. No live or synthetic reproduction was performed, and this is not a general cross-tenant or host-execution claim. Archiving a member alone is not equivalent to removing read scope: the existing policy permits archived-member reads while membership persists.

**Smallest proposed correction:** retain structured member ID, original workgroup and repository/branch binding in each pending item; re-resolve current allowed relationship and relevant grants immediately before releasing notification text, coordinated with membership mutation admission. Drop removed/moved/deleted or otherwise unauthorized items. A pre-flush snapshot alone leaves an I/O-to-delivery race. Preserve already-authorized archived-member read policy rather than inventing a blanket archival denial. If implementation is deferred, the existing `AMUX_PR_POLL_INTERVAL=off` disables this optional subsystem (`internal/daemon/prwatch.go:34–61,77–86`); apply only through the release owner's authorized configuration flow. This does not disable CREATE, control, either runtime, host identity or the account broker.

**Proposed focused tests, not run:** fake watcher members/runner/delivery, enqueue then move/delete/remove repo grant, then flush; assert no old-destination text, with unchanged-current-member positive control. Add an admission-level stale-observation check at the delivery seam. Existing deferred/stale tests (`internal/prwatch/prwatch_test.go:294,323`) cover busy delivery and age, not changing scope.

**Adjacent acceptance limit:** readiness/goal checks precede `d.handle` (`prwatch.go:218–227,256–290`); unknown Claude goal status after read failure becomes empty and skips the goal-status refusal (`:349–365`). A known paused/input/complete state is refused at that check, but this source does not establish an atomic guarantee against a concurrent pause/new permission prompt. Add a bounded delivery-seam test for state changing during admission; treat unknown goal state conservatively when a goal-enabled coordinator is being automatically resumed. This is a source/design observation, not proof that an approval was answered or a paused live goal resumed.

## Signing, revocation, withdrawal and progress

**Observed / judgment:** `FileAuthority.SignIssuer` now signs through an immutable atomic issuer-key snapshot instead of taking the subject registry read lock (`internal/access/authority.go:329–349`). Subject rotation/revocation still determines `Valid`/`Verify`; an issuer signature is authenticity of an exact service/result record, not a new subject grant. The mailbox still verifies requests, validates generation before authorization and again before dispatch; the dispatcher owns final live policy checks (`internal/sessionrpc/server.go:711–758`; `internal/daemon/session_dispatch.go:124–157,267–282`). Client response verification still binds boot, subject, key, generation, request ID and body digest (`internal/sessionrpc/client.go:349–369`). [Signer](https://github.com/Kchymet/agent-multiplexer/blob/105030b31094f8a6ff557263d5c26d4eb7a3a8ac/internal/access/authority.go#L329), [response binding](https://github.com/Kchymet/agent-multiplexer/blob/105030b31094f8a6ff557263d5c26d4eb7a3a8ac/internal/sessionrpc/client.go#L349).

An in-flight signature may finish across authority Close; that does not restore a revoked credential. Signing an already-admitted result likewise does not imply the old principal can execute another request. The new concurrent signing/rotation test checks old generation rejection (`internal/access/issuer_signer_test.go:115–191`). CI passes its package; no local `-race` claim is made. Lock-wait instrumentation measures waiting; it does not make registry lock acquisition context-cancellable.

**Observed / contract:** unclaimed request withdrawal races the server's rename using an unlink relative to the held requests directory. Successful withdrawal returns `ErrNotExecuted`; a claimed/missing/unremovable request remains indeterminate absent a verified result (`client.go:273–345`). Abandoned-expiry inspection only discards an old request; it cannot grant execution (`server.go:606–630`). Existing tests distinguish unclaimed deadline, claimed indeterminate result, expired withdrawal and unanswered old backlog (`request_withdraw_test.go:26,58,80,132`). Do not turn timeout, disconnect or uncertain outcome into automatic replay with a fresh request ID. [Withdrawal](https://github.com/Kchymet/agent-multiplexer/blob/105030b31094f8a6ff557263d5c26d4eb7a3a8ac/internal/sessionrpc/client.go#L273).

**Observed / contract:** new `deadline_exceeded` classification is for a callback failing policy lookup or self-completion lookup before effects (`session_dispatch.go:169–178,207–226`). It is not a universal cancellation barrier after admission. In particular, the PR guard can time out and allow an already-admitted archive; `SetArchived` performs its store write without consulting ctx (`internal/wsops/prguard.go:155–178`; `internal/wsops/wsops.go:930–962`). Callbacks remain synchronous and preserve deferred-work serving lifetime (`session_lifecycle.go:418–458`). This is compatible with an indeterminate claimed request, not a promise of no effect at the client deadline. If the product requires cancellation after guard I/O but before archival, add an explicit check at that boundary rather than broadening the meaning of the new error code. No incorrect `deadline_exceeded` result after a demonstrated effect was established.

**Observed:** shared `publishMu` now serializes response-directory scans during initialization, reservation and publication (`server.go:345–347,921–943,1258–1261`), addressing the shared directory iterator race while retaining bounded response admission. `TestFastReservationAndSlowPublicationShareResponseScan` exercises both lanes (`response_scan_race_test.go:15–53`). Its package passes ordinary CI; race-detector verification of this exact candidate remains separate evidence, not something inferred from green CI.

The provider CREATE/final-grant implementation is unchanged in this delta. Nothing reviewed introduces a prestarted-task requirement, view-only beta, weakened account identity or a Codex/Claude parity assumption. Existing owner/session checks and the previously reviewed late-CREATE correction remain dependencies, not re-proven here.

## PR operations, diagnostics and runtime choices

**Observed:** the new `force` field bypasses only the advisory open-PR guard. Policy still denies self force; a coordinator may force archival of a current direct member, not its own root or foreign members; delete/kill stay host/delegated-console operations (`internal/access/scope.go:44–67,133–149`; role-matrix tests `policy_test.go:65–72`). Own-member archival itself predates this delta; PR249 primarily changes guidance/reminders. Restore and coordinator grant mutation remain host-only. [Policy](https://github.com/Kchymet/agent-multiplexer/blob/105030b31094f8a6ff557263d5c26d4eb7a3a8ac/internal/access/scope.go#L133).

The PR guard explicitly fails open on GitHub/store errors/timeouts; host toggle-archive is excluded (`internal/wsops/prguard.go:65–102`). Its `gh pr list` reads at most 200 open PRs and filters by stored branch (`internal/ghpr/ghpr.go:51–83`). This is not an enforced universal “never archive any open PR” safety property. It uses useful host GitHub identity intentionally; it does not grant sessions the host credential. Formatted refusal exposes only scoped PR identifiers/branches/URLs; other action errors remain scrubbed (`session_dispatch.go:228–243`). A hard workflow requirement would need a separate policy decision, not a vulnerability label for documented fail-open behavior.

**F2 — observed source / lower-priority hardening:** new request timing copies unverified `Call.Kind` before call validation (`internal/sessionrpc/server.go:79–88,671–681`) and later formats it using `%s` in daemon logs (`internal/daemon/session_stall_log.go:44–50`). Unlike request IDs (hex shape checked) and verb (filtered), Kind is not allowlisted/escaped there. A malformed bounded own-mailbox envelope with an old positive IssuedAt can reach the age-triggered timing path even if signature/call validation rejects it. **Inference:** newline/control text in Kind can forge log presentation or amplify a diagnostic line; this is local audit-integrity/log hygiene, not proof of secret disclosure or authorization bypass. Sanitize to recognized kind/unknown, or bound and quote it; test rejected envelopes preserve a single bounded log record. [Timing input](https://github.com/Kchymet/agent-multiplexer/blob/105030b31094f8a6ff557263d5c26d4eb7a3a8ac/internal/sessionrpc/server.go#L79), [log formatting](https://github.com/Kchymet/agent-multiplexer/blob/105030b31094f8a6ff557263d5c26d4eb7a3a8ac/internal/daemon/session_stall_log.go#L31).

SIGUSR1 diagnostics emit all goroutine stacks into the local daemon log (`internal/daemon/goroutine_dump.go:15–47`). Treat these as operator diagnostic artifacts containing stack/path/runtime metadata, not a guaranteed secret-free support attachment. This delta does not add an upload or a restricted-session dump API. Do not send SIGUSR1 to an older binary without this handler. PR metadata/check names are also untrusted external data: the watcher appends them into prompts (`internal/prwatch/gh.go:41–67,103–105`; `prwatch.go:532–535`; `internal/daemon/prwatch.go:236–250`). They are not a new user grant or merge approval; no prompt-injection execution was tested.
